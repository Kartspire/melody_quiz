# Исправления по полному ревью

Этот файл фиксирует изменения, внесённые после полного ревью проекта, с приоритетом на медиатеку, IndexedDB и переносимые архивы.

## Хранение аудио

- `AudioAsset` стал content-addressed: `id === sha256`, `sha256` обязателен, дублирующее поле `size` удалено.
- Новые файлы хешируются и проверяются до попадания в state. Одинаковое содержимое переиспользует существующий Blob.
- Старое хранилище мигрируется при загрузке: старые ID перепривязываются, одинаковые Blob объединяются. Legacy `app-state` удаляется после успешной миграции.
- Валидация известного формата проверяет сигнатуру файла; в реальном браузере дополнительно используется `loadedmetadata`.
- Для больших Blob SHA-256 и CRC32 считаются в Worker, чтобы синхронный CRC-проход не блокировал UI.

## Import / export

- Вынесены схема и validator формата (`melodyPackageSchema.ts`), заложен switch для миграций следующих `formatVersion`.
- Введены лимиты размера пакета, JSON, одного аудио, числа файлов/песен и пользовательских строк.
- Проверяются SHA-256 и CRC каждого файла, в том числе `manifest.json`; незаявленные и дублирующиеся ZIP entries запрещены.
- ZIP reader дополнительно проверяет EOCD/central/local bounds, флаги, имена, compression method и совпадение local/central metadata.
- Export выполняет те же структурные проверки и собственные size/file-count limits, поэтому не создаёт пакет, который приложение само не сможет принять.
- Импорт больше не хеширует всю существующую медиатеку.
- Подтверждение импорта пересчитывает merge относительно последнего Effector state, а не применяет snapshot момента выбора файла.
- Статистика различает уже существовавшие песни/аудио и дедупликацию внутри самого архива.
- Конфликт `gameId` по-прежнему поддерживает replace/copy; заголовок копии безопасно ограничивается максимальной длиной.

## IndexedDB и конкурентность

- Обычные записи стали entity-level diff вместо `clear()` всех stores.
- Все сохранения проходят через последовательную очередь.
- Добавлена `state-revision`; запись возможна только поверх ожидаемой ревизии.
- `BroadcastChannel` сообщает другим вкладкам о новой ревизии. Устаревшая вкладка блокируется и требует reload.
- Ошибка первоначального чтения не открывает редактор с initial state, чтобы случайно не затереть существующую БД.
- При `visibilitychange`/`pagehide` pending snapshot отправляется на сохранение без ожидания debounce.
- В настройках доступны `navigator.storage.estimate()`, `persisted()` и явный `persist()`.

## Валидация и игровая модель

- Разделены draft-safe validation локального редактора и строгая validation импорта/экспорта/старта игры.
- Валидируются timestamps, размеры/длины, уникальность ID, команды, цвета, points, ссылки `question -> song -> audio`.
- Продолжение партии игнорирует требования к аудио уже завершённых вопросов.
- Вынесена чистая session-логика (`session.ts`); старые сессии reconciled с текущими командами/вопросами.
- Усилены domain guards для открытия вопросов, начисления баллов, неверных ответов, перехода раунда, song assignment и уникальных points.
- Существующая логика «ошибившаяся команда не отвечает повторно в этой песне и пропускает следующую» сохранена.

## UI / производительность

- Для lookup песен/аудио на больших досках используются `Map` вместо повторных линейных `.find()` в каждом элементе.
- Изменение общей песни явно предупреждает о влиянии на несколько игр; можно создать отдельную копию, которая использует те же immutable audio blobs.
- Статус автосохранения отображается в sidebar; при конфликте вкладок пользователь получает безопасный экран reload.
- Настройки показывают как размер аудио приложения, так и реальное browser storage usage/quota.

## Тесты

Добавлены/расширены тесты:

- `melodyPackage.test.ts` — round-trip, повторный импорт, библиотека, внутренняя дедупликация, повреждение байтов;
- `zipStore.test.ts` — round-trip и malformed ZIP;
- `validation.test.ts` — структурная/draft validation и continuation;
- `session.test.ts` — reconciliation и завершение раунда;
- `audio.test.ts` — пустые/явно повреждённые сигнатуры.

Существующий атомарный порядок импорта сохранён: IndexedDB commit завершается до применения импортированного state в Effector.
