# Исправления по полному ревью

Этот файл фиксирует изменения, внесённые после полного ревью проекта, с приоритетом на медиатеку, IndexedDB и переносимые архивы.



## Межраунды v1.5.1

- `commonTheme4` переведён на templateVersion 2 с массивом внутренних этапов `stages[]`; каждый этап содержит 4 трека и собственную общую тему.
- Добавлены add/remove этапов, сохранение `taskIndex + trackIndex` и последовательный переход между наборами.
- Добавлена автоматическая миграция старого `commonTheme4` v1 и его сохранённого прогресса.
- Melody package format повышен до v4 с обратным импортом v1–v3.
- Управление порядком игровых stages переведено с текстовых стрелок на единый компактный SVG-control.

## Межраунды v1.5.0

- добавлена stage-модель для единой последовательности обычных раундов и межраундов;
- реализован registry шаблонов межраундов с версиями и двумя независимыми конфигурациями;
- добавлены шаблоны «Продолжи песню» и «4 трека — общая тема» с отдельными editor/player;
- inter-round audio ссылается непосредственно на `MediaTrack`, учитывается при удалении и попадает в экспорт игры;
- сессии сохраняют `stageIndex`, завершённые межраунды и прогресс внутри текущего межраунда;
- formatVersion `.melody` повышен до v3, старые v1/v2 и старый `roundIndex` мигрируются автоматически.

## Единая медиатека v1.4.0

- Между игровой сущностью `Song` и физическим `AudioAsset` добавлен `MediaTrack`. `MediaTrack` не требует музыкальных метаданных и может использоваться будущими межраундами напрямую.
- `Song` теперь содержит `minusTrackId` / `plusTrackId`; исполнитель и название остаются только на уровне классической песни.
- В UI медиатеки появились вкладки «Песни» и «Аудио». Обычная песня может выбрать существующий трек либо создать новый при загрузке файла.
- Свободный `MediaTrack` можно создать отдельно, переименовать, прослушать, заменить его физический файл или удалить при отсутствии ссылок.
- Замена файла сохраняет ID `MediaTrack`, поэтому все текущие ссылки продолжают работать; неиспользуемый старый Blob очищается автоматически.
- Физические `AudioAsset` при повторном добавлении того же SHA не перезаписываются случайными именами и остаются одной immutable content-addressed записью.
- IndexedDB schema поднята до версии 4 с store `media-tracks`; старые `Song.minusAudioId` / `plusAudioId` мигрируются автоматически.
- Melody package format поднят до v2: добавлен `tracks.json`. Парсер по-прежнему принимает v1 и преобразует старые прямые audio refs в `MediaTrack` на лету.
- Library export включает самостоятельные медиатреки, поэтому будущие межраундовые ассеты резервируются даже без `Song`.

## Хранение аудио

- `AudioAsset` стал content-addressed: `id === sha256`, `sha256` обязателен, дублирующее поле `size` удалено.
- Новые файлы хешируются и проверяются до попадания в state. Одинаковое содержимое переиспользует существующий Blob.
- Старое хранилище мигрируется при загрузке: старые ID перепривязываются, одинаковые Blob объединяются. Legacy `app-state` удаляется после успешной миграции.
- Валидация известного формата проверяет сигнатуру файла; в реальном браузере дополнительно используется `loadedmetadata`.
- Для больших Blob SHA-256 и CRC32 считаются в Worker, чтобы синхронный CRC-проход не блокировал UI.

## Import / export

- Вынесены схема и validator формата (`melodyPackageSchema.ts`), заложен switch для миграций следующих `formatVersion`.
- Введены лимиты размера пакета, JSON, одного аудио, числа файлов/песен и пользовательских строк.
- Проверяются SHA-256 и CRC каждого файла, в том числе `manifest.json`; незаявленные и дублирующиеся ZIP entries запрещены.
- ZIP reader дополнительно проверяет EOCD/central/local bounds, флаги, имена, compression method и совпадение local/central metadata.
- Export выполняет те же структурные проверки и собственные size/file-count limits, поэтому не создаёт пакет, который приложение само не сможет принять.
- Импорт больше не хеширует всю существующую медиатеку.
- Подтверждение импорта пересчитывает merge относительно последнего Effector state, а не применяет snapshot момента выбора файла.
- Статистика различает уже существовавшие песни/аудио и дедупликацию внутри самого архива.
- Конфликт `gameId` по-прежнему поддерживает replace/copy; заголовок копии безопасно ограничивается максимальной длиной.

## IndexedDB и конкурентность

- Обычные записи стали entity-level diff вместо `clear()` всех stores.
- Все сохранения проходят через последовательную очередь.
- Добавлена `state-revision`; запись возможна только поверх ожидаемой ревизии.
- `BroadcastChannel` сообщает другим вкладкам о новой ревизии. Устаревшая вкладка блокируется и требует reload.
- Ошибка первоначального чтения не открывает редактор с initial state, чтобы случайно не затереть существующую БД.
- При `visibilitychange`/`pagehide` pending snapshot отправляется на сохранение без ожидания debounce.
- В настройках доступны `navigator.storage.estimate()`, `persisted()` и явный `persist()`.

## Валидация и игровая модель

- Разделены draft-safe validation локального редактора и строгая validation импорта/экспорта/старта игры.
- Валидируются timestamps, размеры/длины, уникальность ID, команды, цвета, points, ссылки `question -> song -> mediaTrack -> audio`.
- Продолжение партии игнорирует требования к аудио уже завершённых вопросов.
- Вынесена чистая session-логика (`session.ts`); старые сессии reconciled с текущими командами/вопросами.
- Усилены domain guards для открытия вопросов, начисления баллов, неверных ответов, перехода раунда, song assignment и уникальных points.
- Существующая логика «ошибившаяся команда не отвечает повторно в этой песне и пропускает следующую» сохранена.

## UI / производительность

- Для lookup песен/аудио на больших досках используются `Map` вместо повторных линейных `.find()` в каждом элементе.
- Изменение общей песни явно предупреждает о влиянии на несколько игр; можно создать отдельную копию, которая использует те же immutable audio blobs.
- Статус автосохранения отображается в sidebar; при конфликте вкладок пользователь получает безопасный экран reload.
- Настройки показывают как размер аудио приложения, так и реальное browser storage usage/quota.

## Тесты

Добавлены/расширены тесты:

- `melodyPackage.test.ts` — round-trip, повторный импорт, библиотека, внутренняя дедупликация, повреждение байтов;

## Надёжность после глубокого ревью

- Импорт и полное восстановление переведены в режим исключительной замены состояния. Пока операция выполняется, изменения через core stores блокируются, повторный импорт не запускается, а асинхронная запись, начатая до замены состояния, не может примениться поверх уже импортированных данных.
- При ошибке импорта локальное состояние возвращается к snapshot, существовавшему до начала операции.
- `reconcileSession` сохраняет действующий `selectingTeamId`, если пользователь остаётся на том же игровом этапе. Команда с минимальным счётом выбирается заново только при переходе на другой этап либо если сохранённая команда больше не существует.
- Диалоги используют стек открытых окон: Escape обрабатывает только верхний диалог, Tab/Shift+Tab удерживают фокус внутри него, а после закрытия фокус возвращается на элемент, с которого окно было открыто.
- При ошибке первоначального чтения IndexedDB доступен отдельный экран восстановления. Full backup сначала проходит парсинг и валидацию, затем состояние записывается атомарно через `restoreState`.
- Настроено React test environment для `act(...)`; regression-тест освобождения vocal-removal модели разделяет рендер и продвижение fake timers.
- Добавлены ручные browser regression checks в `tests/browser`: реальные IndexedDB транзакции, rollback при ошибке, восстановление повреждённой записи, сохранение выбирающей команды и конфликт между двумя вкладками через revision/BroadcastChannel.
- README приведён в соответствие с фактически существующими npm-командами и файлами проекта. Браузерные проверки документированы отдельно и не выдаются за автоматический CI/E2E gate.
