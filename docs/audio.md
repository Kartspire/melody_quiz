# Аудио-пайплайн

## Хранение

Физические файлы представлены `AudioAsset` и адресуются SHA-256. Реальный контейнер определяется по сигнатуре байтов, а MIME/расширение рассматриваются как метаданные и проверяются на противоречия.

Поддерживаемые контейнеры централизованы в audio domain: MP3, WAV, OGG/Opus, FLAC и M4A/MP4.

`verified` означает целостность content-addressed записи и не является самостоятельной гарантией поддержки кодека конкретным браузером. Browser playback validation выполняется на входных границах данных.

## Playback

Все основные плееры используют `useAudioPlayer`, который отвечает за:

- source lifecycle;
- play/pause/toggle;
- seek и timeline state;
- `startAt` / `stopAt`;
- range end policy;
- ошибки `play()`;
- cleanup listeners и RAF.

Игровая семантика остаётся в конкретных компонентах (`AudioQuestion`, межраунды, preview), а playback engine общий.

## Vocal removal

HTDemucs запускается в отдельном Worker. Отмена уничтожает Worker, поэтому ONNX inference не продолжает работать после ухода со страницы.

Безопасные ограничения задаются централизованно:

- максимальный исходный файл — 100 МБ;
- максимальное browser decode окно — 8 минут;
- один запуск vocal removal — до 90 секунд.

Для длинных записей пользователь сначала выбирает нужный фрагмент.

ML runtime по-прежнему загружается лениво с зафиксированных внешних URL. Это остаётся отдельным deployment-техническим долгом: для полностью offline/self-hosted режима runtime и модель нужно разместить вместе с приложением.
